# Tauri 后端约定

## 目录职责

- `src/commands.rs` 只定义 Tauri 命令和参数转发，不承载业务逻辑。
- `src/controller.rs` 负责业务编排、项目 ID 校验和事件广播。
- `src/services/` 负责配置、扫描、Git、进程和系统打开能力。
- `src/utils/` 只放无业务状态的通用函数。
- `src/models.rs` 定义 IPC 与持久化模型，字段使用 camelCase 序列化以兼容前端。

## 安全约束

- 前端不得传入任意工作目录；所有路径必须通过已登记的 `projectId` 解析。
- Git 命令使用程序与参数数组执行，禁止拼接 shell 字符串。
- 自由格式启动命令仅允许在已登记项目目录中通过 `cmd.exe /D /S /C` 执行。
- 不向前端开放 Shell、文件系统或 Opener 插件的宽泛权限。
- 打开外部地址前必须校验协议；项目目录和编辑器协议必须由后端生成。

## 进程约束

- 每次启动生成递增代次，旧进程事件不得覆盖新进程状态。
- Windows 停止操作必须终止完整进程树。
- stdout、stderr 必须异步消费，并限制内存中的日志行数。
- 所有外部命令必须配置超时，并返回退出码和 stderr。

## 代码与测试

- 新函数必须包含完整类型签名；非直观逻辑使用简短中文注释。
- Rust 代码必须通过 `cargo fmt --check`、Clippy 和单元测试。
- 文件系统测试使用临时目录，禁止读写用户真实配置。
- 进程测试必须清理所有测试子进程。
